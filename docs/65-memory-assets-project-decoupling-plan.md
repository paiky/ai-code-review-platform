# 记忆资料与项目解耦及项目关联简化计划

- 日期：2026-11-13。
- 状态：A1～A5 已依序完成并逐阶段本地提交；用户授权的当前本地库 V60 迁移已完成且验收通过，不涉及 test 或部署库。
- 基线：U1～U5 已完成，最新代码提交 `bffbed7`。本文接续 [64 号专项](64-memory-library-simple-ui-plan.md)，不修改其已完成记录；资料解析、人工确认和冻结背景继续沿用 [62 号专项](62-agent-review-memory-library-plan.md)，关系并发保护沿用 [63 号专项](63-memory-library-central-management-plan.md)。
- 用户确认的目标：上传不再选择项目，关联单独处理；“项目关联”成为同级 Tab，简化现有项目使用配置。
- 每阶段完成实现、对应验收和记录后先本地提交，再停止；用户后续明确授权连续阶段时按授权顺序逐阶段提交，不重复请求确认。不推送、部署、调用真实模型或默认开启真实项目记忆。

## 1. 最终使用链路

普通资料：**上传规范 / Skill / 架构约定 → 核对草稿并发布 → 项目关联 → 项目开启记忆 → 后续 Agent Review 按变更匹配。**

误报案例：**任务标记误报 → 人工整理五段案例并确认 → 异步生成本项目案例及默认关联 → 后续按变更匹配。** 案例不改成公共资料，不再要求用户额外手动关联一次。

| 同级 Tab | 主要操作 |
| --- | --- |
| 上传资料 | 拖拽 / 多选文件；必要字段仅资料类型、适用端。保持“不限”选项、文件名默认标题和高级设置，无项目字段 |
| 记忆资料 | 查看、筛选、编辑、核对发布资料；展示“公共资料 / 旧项目资料”及使用项目，支持从资料侧管理使用项目 |
| 案例与打标 | 保留 U5 全局反馈、人工确认、来源追溯及案例目录；案例显示所属项目 |
| 项目关联 | 选择项目，查看已关联资料、添加 / 移除资料，开启 / 关闭该项目记忆；高级范围折叠 |

“公共资料”表示平台资料库中的管理资产，不是任何人可匿名读取，也不等于已经用于所有项目。

## 2. 数据语义与兼容边界

### 2.1 最小模型调整

- 保留 `review_memory_sources` 和 `review_memory_project_sources`，不复制正文、不建虚拟项目，也不增加第二份关联配置。
- 将来源表 `project_id` 调整为可空。NULL 仅表示独立公共资料；非空继续保留旧资料维护项目或案例所属项目的原含义。资料归属与是否有关联是两个不同事实，不按“关联数为零”推断资料属于公共库。
- 公共资料仅允许 STANDARD / SKILL / ARCHITECTURE，且不能是 FEEDBACK 来源；新建默认 DRAFT，`visibility=SHARED` 表示发布后可供项目显式选择，不自动建立任何关系。草稿、停用、删除、未首次发布的替换稿仍不可引用。
- PITFALL / INCIDENT 和所有 FEEDBACK 来源仍必须有真实项目，保持 PROJECT 范围及跨项目引用禁令。手工创建案例也继续选择项目。
- 不新增持久化 scope 字段；管理 DTO 可根据 projectId 是否为空返回 `assetScope=LIBRARY/PROJECT`，让前端直接区分管理路由与显示文案。不能用 `String(null)`、空字符串或 0 拼项目接口。
- 共享引用及项目使用摘要需要承载公共资料时，来源 `projectId` / 快照 `ownerProjectId` 可为 null；关系 `projectId`、任务 `projectId`、快照审查项目仍是非空真实项目。已有资料的数字值不改变；OpenAPI 和所有消费方须明确新值域。

### 2.2 旧资料与历史任务

- 不批量清空旧来源 project_id，不自动改共享范围、发布状态、自关联、使用范围、项目开关或来源版本。不因新增公共库，把原私有规范自动暴露给其他项目。
- 旧项目规范 / Skill / 架构资料继续可管理和关联；跨项目仍要求其原共享条件。页面标明“旧项目资料”，避免误认为必须重新上传。暂不提供归属转移或整库转公共资产。
- 案例确认和回写继续使用原项目 API、反馈 digest / 来源 version、幂等和失效钩子；不移动旧案例，不放宽确认条件。
- 已入队 / 已完成任务的冻结文本及版本、采用摘要不回填；新公共资料只可能影响后续入队任务。Standard 和 fallback 行为保持不变。

### 2.3 管理、引用和预算必须分别处理

- 原共享目录只允许已发布有效章节；公共资料草稿及原件由显式管理接口读取，不把“调用时 project_id=None”当成归属身份。尤其需要修正 `None == None` 被误判为 owner 的边界。
- 现有可信管理部署边界不变，不新增账号 / RBAC；项目引用接口只能读取符合条件的资料，不能因支持公共资产获得草稿编辑能力。
- 发布公共资料不再要求“归属项目自关联存在”。未关联任何项目也可发布；格式、章节和 Skill / 案例加载方式校验继续执行。
- 未关联的公共 CORE 章节不占任一项目预算；关联或恢复时校验目标项目预算。已关联资料修改、发布、停用和替换仍校验实际受影响项目并沿用版本及影响确认，不能跳过其他项目的冲突或预算。
- 新公共资料替换稿也不自动关联；首次发布时沿旧规则继承被替换资料的实际关系及范围。公共替换与旧项目替换分开校验，不借替换转移资料归属。
- 文件去重按公共库或原维护项目的真实范围处理；不得通过 NULL 比较失效漏掉重复校验，也不得擅自把旧项目的同名 / 同内容资料合并。

## 3. 项目关联页的最终交互

1. 选择项目；页面只保留“已关联资料”和“添加资料”主操作。默认所有端、所有路径，端和路径收进“高级范围”，不要求普通用户理解两层 glob。
2. “添加资料”默认展示该项目可用的已发布公共资料及原共享资料；旧项目自有规范 / Skill 继续可选。点击预览后显式“关联到该项目”，不能把全局管理目录直接当成可引用目录。
3. 已有关联显示资料名称、类型、发布状态、范围摘要和阻断原因；操作为查看、移除，范围调整为次级操作。已移除资料作为次级入口，支持恢复已保存范围。
4. 项目记忆开关仍需显式保存；关联不自动开启记忆，开关也不自动关联全部资料。文案区分“已关联”“可按本次变更匹配”“本次实际采用”。
5. “本项目案例”作为自动关联来源显示，明确“人工确认后自动关联”。不要求从公共资料候选中添加案例；已移除的本项目案例可按原规则恢复，撤回 / 停用仍不能直接恢复为有效背景。
6. 旧项目反馈及旧策略放入“更多 / 高级信息”，不占据主操作区域。资料侧“管理使用项目”继续操作同一关系；保持逐项保存、失败保留输入和成功结果，不引入跨项目全量覆盖或批量事务。

保留 `/settings/review-memory?tab=projects&projectId=...` 及旧 `/settings/ai-review/memory` 重定向，`projects` 只是显示名称改为“项目关联”。sourceId / 来源反馈 / 原任务深链接继续使用实际归属及正确接口，保留 query / hash 和未保存保护。

## 4. Review 匹配沿用现有规则

1. 读取任务真实项目和已保存的记忆开关；只取该项目 ACTIVE 关系，不扫描所有公共资料强行注入。
2. 过滤资料及章节发布状态、共享 / 案例合法性、任务端与变更路径；关系范围和章节范围同时满足。
3. 已匹配范围的 CORE 按原强制预算处理；ON_DEMAND 从问题信号、路径 / diff 关键词及通用兜底召回，再按端、路径具体程度、问题及关键词命中排序。
4. 校验反馈案例有效性，与旧策略及相同正文去重，沿原条目数 / 字节预算选择，冻结文本、版本、采用原因后入队。

不修改召回算法、问题信号、预算或 Agent 容器；Skill 仍只提供文本，不执行脚本；不加入 AST、调用图或向量库。本次检索改动只用于识别合法的无归属公共资产，不能减少关联及发布检查。

## 5. 契约落点

以下为实施目标，A1 / A4 写代码前须以 Pydantic DTO 和 OpenAPI 固化；旧项目写 API 不改变路径或默认创建语义。

| 契约 | 变化 |
| --- | --- |
| 全局管理列表与关系摘要 | 来源 projectId 支持 null，新增可计算 assetScope；保留分页 / 分类 / 端摘要及最多 3 个使用项目摘要。补充公共 / 旧项目筛选时必须服务端计数，不能前端过滤单页 |
| `GET /api/review-memory/sources/{id}` 及管理原件读取 | 新独立管理读取；公共资产可查看草稿 / 原件。旧项目及反馈来源沿既有管理限制，不扩展共享引用正文 |
| `GET /api/review-memory/capabilities` | 仅返回本功能所需的 schemaReady（可空归属迁移是否就绪）；不是新的配置中心。迁移前不开放公共创建，并提供明确未就绪提示 |
| `POST /api/review-memory/uploads` | 无项目 multipart 上传；沿原 metadata、解析、大小和超时限制，仅创建公共普通资料草稿，不建项目关系 |
| `POST /api/review-memory/sources` | 手工创建公共普通资料；案例继续原项目入口 |
| 公共资产详情 / 章节修改、发布、影响预览、停用、原件及替换 | 在管理 sources 下补齐原操作对应资源路径，复用事务 / 版本 / 影响确认，不另造编辑器契约。公共写必须校验 project_id IS NULL、普通资料类型及非反馈来源 |
| 项目关联 / 恢复 / 移除与项目设置 | 保留原项目路径及 CAS；允许显式添加已发布公共普通资料，其余限制不变。关联永远有真实 projectId |

迁移未就绪时公共创建返回明确业务错误，不能等 INSERT 报 500，也不回退创建到某个默认项目。拒绝公共案例请求必须在写入前发生。所有新写操作同原接口有事务回滚；不增加自动重试写入。

## 6. 分阶段实施

| 阶段 | 交付边界 | 改动量等级 | 浏览器验收 |
| --- | --- | --- | --- |
| A1 | 后端无归属资料读取兼容与边界保护 | 中 | 不需要 |
| A2 | 前端四 Tab、无归属资料读取与路由兼容 | 中 | 必须 |
| A3 | 可空归属迁移及就绪识别 | 中 | 不需要 |
| A4 | 后端公共资产独立写入、发布与显式关联闭环 | 中 | 不需要 |
| A5 | 前端上传解耦、关联操作简化及最终回归 | 中 | 必须 |

首次评估整体同时涉及 schema、读写接口和 UI，属于大改动，已按“先兼容读取 → 迁移 → 后端完整写闭环 → UI 开放”拆分。每阶段可单独交付，不保留大阶段，也不在后端边界完成前开放无项目上传。

### A1：后端读取兼容与边界保护

- **改动量等级：中。** 仅 Python 读取与契约兼容，涉及共享 / 项目 / 管理读取及冻结摘要的可空值，无数据库执行和新创建能力。
- **目标 / 范围：** 明确 nullable projectId / ownerProjectId 和 assetScope；新增显式管理详情 / 原件读取；审计 owner 判定、null 项目过滤、正文读取、引用摘要、项目预算查询及快照校验。普通公共资料需要真实 ACTIVE 关系才能成为候选；无项目案例不合法。原项目写入口仍只写非空真实项目。
- **非目标：** 迁移、新公共写入口、改前端、批量转换旧资料、改变匹配算法。
- **验收：** ruff / compileall、随机隔离 MySQL / API 构造可空表样本验证公共草稿管理可读但共享 / 项目不可读、公共已发布仅正确关联可用、null 不能变 owner、案例不可跨项目、来源摘要和新旧冻结 payload 可解析；旧字段及原项目资料行为保持一致。按项目约定不默认新增 / 修改 / 运行单元测试。
- **授权 / 停止点：** 后续获 A1 实施授权后推进；不写真实数据库。兼容读取独立可用后记录、提交并停止，无公共资产创建者。

### A2：四 Tab 与读取兼容

- **改动量等级：中。** 仅 React 多组件及旧链接适配，消费 A1，不增加写能力。
- **目标 / 范围：** 展示四个同级 Tab，移除标题旁重复的项目使用配置主按钮；旧 projects 参数继续有效。所有资料详情、来源、原件、绑定摘要和历史采用摘要按 assetScope 分路由，禁止 null 项目请求。公共资产先支持查看；编辑入口在公共写链路可用前不开放。旧项目资料编辑、U3 上传和 U5 案例操作保持可用。
- **非目标：** 提前删除上传项目字段、公共发布 / 编辑、关联交互整体重写。
- **验收：** 统一前端 build、隔离浏览器验证四 Tab、公共 / 旧项目 / 案例详情、正确接口、原件和快照摘要、旧 URL / 参数 / hash、未保存保护与 390px。真实页面仅只读。
- **授权 / 停止点：** 后续获 A2 授权后实施；只对隔离响应写入。新建仍为旧项目上传；记录、提交后停止。

### A3：可空归属迁移与就绪识别

- **改动量等级：中。** 单库单表放宽空值及局部就绪读取，需迁移兼容与回退验证；不跨端搬迁存量数据，不改变旧字段值，也不增加可见写入口。与后端公共写入、前端开放拆开交付。
- **目标 / 范围：** 新增增量迁移将来源 project_id 放宽为空（当前版本至 V59，实施时核对下一空闲版本号，不改 V57 / V58 历史文件）；同步 ORM。增加有界 capabilities / 写入前检查所需的 schema 检测，迁移前后均可读取。就绪状态不能依赖进程启动时永不刷新的缓存。
- **非目标：** 删除旧归属、自关联或数据，放宽案例语义、重建表、创建无归属资产。
- **验收：** 隔离 MySQL 从旧结构执行升级，验证全部行 / 关系 / 版本不变、可空列就绪；全新建库与既有迁移顺序均可用；未升级时返回明确未就绪，原项目 API 正常。需要记录 DDL 非事务特性、备份及失败检查步骤；无浏览器验收要求。
- **授权 / 停止点：** A3 默认只交付迁移和隔离演练；执行用户实际本地或部署库迁移需获得明确目标授权后按操作步骤执行。不要因启动脚本会自动迁移而在验收中启动真实服务。提交后停止；未迁移的部署继续使用旧链路。
- **回退：** 无 NULL 来源时可在检查后恢复 NOT NULL；已有公共资料时不能直接降级旧后端 / 强行回填某个项目，须保留兼容代码并单独安排资料处理。不得通过删除新资料实现自动回退。

### A4：公共资产后端写入闭环

- **改动量等级：中。** 仅 Python 资料写入及项目关联模块，消费已定义契约和 A3 迁移，不改表结构或前端。
- **目标 / 范围：** 完成无项目上传 / 手工普通资料创建及全部必要生命周期操作；不创建默认关系。管理写入口仅处理合法公共普通资料，旧项目资料继续原项目 API。补齐显式关联、CORE 预算 / 影响预览 / 替换关系继承、重复校验和召回的公共资产适配；不在 API 创建后留下无法发布或维护的草稿。
- **非目标：** UI 开放、公共案例、自动关联 / 自动开启、批量发布、修改预算 / 排序 / 反馈确认机制。
- **验收：** 静态检查、隔离真实 multipart / MySQL 验证 MD / DOCX / PDF / Skill 独立草稿→无关联发布→显式关联两个项目→各自范围→冻结选择；未关联不可采用，关闭 / 端路径不符不可采用。覆盖项目 CORE 预算冲突、source / binding CAS、替换、影响确认、停用 / 移除、原件读取、重复文件、非法公共案例和未迁移阻断；原项目规范及误报案例完整旧链路回归。无真实模型调用，无浏览器要求。
- **授权 / 停止点：** 获 A4 授权且隔离 schema 就绪后推进，不操作真实资料或配置。后端全闭环可独立使用后提交并停止，前端仍未开放无项目创建。

### A5：上传解耦与关联简化

- **改动量等级：中。** 仅 React 多组件交互，消费 A1～A4 的完整能力；无需新后端契约或迁移。
