# 项目记忆库集中管理与关联交互调整计划

- 日期：2026-11-13。
- 状态：C1 已完成并通过验收；C2/C3 尚未实施。基线为 M1～M9、S1～S3 已完成，前序功能提交 `86ecf7a`；C1 提交号以 Git 记录为准。
- 本文负责菜单、集中管理及项目关联体验调整；资料解析、发布、反馈沉淀、检索和冻结快照沿用 [62 号专项](62-agent-review-memory-library-plan.md)。不替代其安全约束，不推进 M10。
- 拆为 **3 个可独立验收的阶段 C1～C3**。每阶段单独授权；完成验收、更新本文并本地提交后停止，不能自动进入下一阶段。

## 1. 本次解决什么问题

现状要求先选择项目，再理解“维护资料”和“本项目使用”，用户容易把资料归属、使用关系与实际审查加载混为一谈。

调整后的操作顺序是：**进入记忆库看资料 → 管理资料 → 分配给项目 → 查看项目使用配置**。项目只在筛选、资料归属和使用配置中出现，不再是浏览资料的前置条件。

最终设置菜单：

```text
设置
├─ 项目 / 端类型配置
├─ AI Review 配置
├─ 项目记忆库
└─ 全局设置
```

项目记忆库使用两个主要页签：

| 页签 | 页面职责 | 是否先选项目 |
| --- | --- | --- |
| 记忆资料 | 集中查看、搜索、上传和维护代码规范、架构约定、Skill、踩坑案例及事故模式 | 否；归属项目和使用项目都是可选筛选项 |
| 项目使用配置 | 选择项目，查看已添加资料、项目记忆开关及每份资料的适用范围 | 是；选择只作用于该页签 |

“维护资料 / 本项目使用”不再作为最终主视图名称。资料详情显示“归属项目”；关联操作显示“使用项目”，避免复用“当前项目”指代两种角色。

## 2. 本轮确定的产品边界

### 2.1 集中展示，保留现有归属

- 保留 `review_memory_sources.project_id` 非空，继续表示资料的归属/维护项目；不新增表、不复制正文、不迁移资料归属，不创建虚拟默认项目。
- 上传/手工新建抽屉增加必填“归属项目”。用户无需先切项目才能看资料，但新建资料仍需明确归属；后端继续使用该项目的原创建接口。
- 已有资料归属不在本轮提供转移；详情、编辑、替换、发布仍使用资料返回的 `projectId`，不能误用页面的使用项目筛选值。
- 沿用新建资料创建自关联的行为。创建表单明确提示“创建后默认添加到归属项目；发布及开启记忆后，仍需按本次变更匹配”。不悄悄改变旧资料的数据意义。
- 若以后要求上传也完全不选归属项目，需另开“独立记忆资产”方案，评估 schema、反馈归属和迁移；不混入本次改版。

### 2.2 集中管理不等于自动共享

- “记忆资料”是平台集中管理视图，列出各项目资料及草稿；新增独立管理查询接口，不放宽现有共享目录或项目引用接口的正文读取条件。
- 仍保留 `PROJECT / SHARED`。代码规范、架构约定和 Skill 显式发布并设为共享后，才能添加到其它项目。
- 踩坑/事故案例及 FEEDBACK 来源仍仅限归属项目，不提供跨项目添加；不能因全局可见而绕过约束。
- 反馈来源只读，编辑需走原人工确认流程。待确认反馈继续在“项目使用配置”选定项目后查看，不扩展全局反馈查询。
- 现有系统没有完整账号/RBAC，`projectId` 不是用户身份。全局管理查询仅适用于现有可信管理部署边界，会集中返回原先分项目可管理的信息；不将“不在共享目录出现”描述为管理员也不可见。不以 UI 隐藏充当鉴权，也不在本次临时新增账号系统。

### 2.3 三种状态分开表达

| 用户看到的状态 | 权威事实 | 不能推断什么 |
| --- | --- | --- |
| 已添加 / 已移除 | 关联 ACTIVE / DISABLED | 不代表资料已发布或本次会加载 |
| 项目记忆关闭、资料草稿/停用、无已发布章节 | 设置、来源与章节的实际状态 | 不自动恢复开关、发布或关联 |
| 按本次变更匹配 | 已添加且基础状态允许作为候选背景 | 不提前保证端/路径/问题线索、去重及预算命中 |
| 本次实际采用 | 任务冻结快照与实际执行 adoption | 不使用当前资料状态补造历史结论 |

本轮不实现新的“模拟必定生效”引擎，不根据两个 glob 字符串简单比较就宣称适用范围有交集。界面展示两层范围，并说明实际由本次变更文件匹配。

## 3. 最终交互

### 3.1 记忆资料

- 默认直接请求全局分页列表，不依次遍历所有项目接口、不将每项目第一页拼成伪全量。
- 分类沿用“规范与约定 / 审查 Skill / 踩坑案例”，可筛选子类型、资料状态、端、问题、归属项目、使用项目和关键词。
- 列表展示名称、类型、发布状态、归属项目、共享范围、已添加项目数量/摘要、更新时间及操作。“使用项目”筛选按 ACTIVE 关联，不等同当前有资格参与检索。
- 操作为“查看 / 编辑”“管理使用项目”；FEEDBACK 来源显示“查看来源反馈”，原件下载及编辑能力仍由服务端契约决定。
- 已添加项目过多时列表只显示最多 3 个名称和总数，完整关系在抽屉分页读取；不在列表加载全文、原件或无限关联数组。
- 删除、停用称为“停用资料 / 删除资料”，确认框明确影响全部使用项目；项目使用配置中称为“从该项目移除”。

### 3.2 从资料管理使用项目

在“Java 开发规范”点击“管理使用项目”，抽屉展示资料归属、发布/共享状态、已添加项目及每个项目的端/路径范围。

- 点击“添加使用项目”，搜索并选择一个项目，填写该项目范围后显式保存；可重复添加其它项目。
- 已添加项目逐行“修改范围 / 移除”；已移除关系可筛选查看并恢复，保留原范围，不物理删除关系。
- 每次只保存一项关系，沿用现有 source/binding 版本校验与项目预算检查。没有跨多个项目的一键全量覆盖、批量事务或默默部分成功；添加 A 成功后添加 B 失败，必须明确保留 A 的成功结果，并让 B 输入可重试。
- 私有资料需先显式共享、草稿需先发布，展示可操作原因；不通过“添加项目”自动共享、发布或开启项目记忆。案例只能展示/管理归属项目的关系。
- 每次成功修改关联都会改变 source.version；刷新资料及关系版本后才能再次保存。409 保留输入，读取最新状态后由用户再次保存，不自动覆盖。

### 3.3 从项目配置使用资料

选择 B 项目后展示：

1. 现有“用于后续 Agent Review”开关及显式保存。
2. B 已添加的自有/共享资料、资料状态、端/路径范围和候选背景提示。
3. “添加记忆资料”：可搜索本项目可用资料和已发布共享资料，预览后添加；不能混用全局管理目录直接绕过引用边界。
4. “查看已移除资料”及恢复操作；已停用、删除或不再可引用的来源保留关系提示，仍允许移除，不伪装成恢复成功。
5. 选定项目的“待确认反馈”入口及旧项目策略只读区，复用既有功能，不丢失 M5 入口。

从资料和从项目进入，编辑的是同一个 `review_memory_project_sources` 关系；后台没有第二份“分配配置”。归属项目变化或资料复制不是关联操作。

## 4. 后端契约与兼容约定

以下为 C1 的目标契约，实施前在 `app/review_memory/schemas.py` 明确 Pydantic 输入/输出并登记 OpenAPI。新字段只用于新端点，不改变旧调用方的默认语义。

| 目标接口 | 用途与有界输出 |
| --- | --- |
| `GET /api/review-memory/sources` | 全局管理分页；可选 `ownerProjectId / usingProjectId / kind / state / targetType / issueType / keyword / pageNo / pageSize`。`pageSize<=100`，默认排除删除，显式状态可查历史；每行保留来源 `projectId`，增加 `activeBindingCount`、最多 3 个 `usingProjectIds` 与 `usingProjectsTruncated`。不返回正文/原件/反馈证据 |
| `GET /api/review-memory/sources/{sourceId}/projects` | 资料关联分页：返回 `sourceId / sourceVersion`，关系 id/projectId/state/version/targetType/pathGlobs；支持 ACTIVE/DISABLED 筛选，默认 ACTIVE，`pageSize<=100`。含失效来源的现存关系，供管理及移除 |
| `GET /api/projects/{projectId}/review-memory/bindings` | 项目关系分页，默认 ACTIVE，可查 DISABLED；返回来源摘要与关联，保留草稿、停用、删除等阻断事实和章节是否有 ACTIVE 条目的事实。来源不存在时给缺失标识，不伪造有效资料；详情可读性单独按原契约判断 |

共同约定：

- 全局列表“归属项目”和“使用项目”是不同查询条件，可同时传；使用项目筛选通过 EXISTS/等价查询避免一份资料因多个关联重复计数。关联统计不得 N+1，不通过每行 impact 请求构造列表。
- 复用旧 DTO 可复用的字段；不为改 UI 同时重写数据模型。分页固定排序（更新时间/id 或关系 projectId/id），总数与过滤语义一致；每次响应内部的版本/关联摘要须一致，但不承诺用户浏览多个分页期间数据绝不变化。
- 上述 GET 只读。详情及正文维护继续走 `/api/projects/{ownerProjectId}/review-memory/...`，ID 必须取来源归属；项目添加、范围保存和移除继续走原 PUT binding 接口。私有/共享、FEEDBACK 只读、source/binding CAS、锁序、预算和影响确认全部保留。
- 原 `GET sources?view=OWNED/USED` 不改变。尤其 USED 目前只列已发布且满足既有可读条件的关联，不能为了管理失效关系而直接改变旧语义；新 bindings 列表负责管理事实。
- 原共享目录继续只返回可共享且已发布资料；新全局管理目录不是它的替代品。无新公开跨项目正文接口，不自动返回私有原件。
- 资料范围与项目关联范围仍取交集，设置默认值、反馈失效、异步写回、入队前关系库检索、32 KiB 快照及 Agent/Standard 行为不改。
- 不新增 schema/迁移。若实施查询出现具体性能瓶颈，再用查询计划提出必要索引及独立迁移边界，不在规划时占用新迁移编号。

## 5. 路由与旧入口兼容

- 新主入口为 `/settings/review-memory`，独立设置 section，与 AI Review 配置同级；默认 `tab=library`。
- 项目使用配置地址示例：`/settings/review-memory?tab=projects&projectId=24`。归属筛选使用 `ownerProjectId`，资料表筛选使用项目使用 `usingProjectId`，不能共用一个参数。
- 旧 `/settings/ai-review/memory`：无参数跳新资料页；带 `projectId` 跳新项目使用配置；带 `projectId/sourceId` 优先打开该项目原本可读的资料详情。历史反馈入口、任务背景的资料链接及 query/hash 兼容映射，不能丢失 sourceId 或将使用项目当归属项目。
- 新全局资料详情可以根据列表中的归属 ID 调用原接口。旧任务引用链接仍遵循原项目可读条件，不能借重定向将失效引用自动升级为管理侧读取。
- AI Review 配置移除记忆页签，保留“模型与运行 / 策略与 Prompt”；已有记忆 UI 环境开关维持显式关闭行为，默认继续显示，不新增开关。
- 保留资料编辑、关联修改、记忆开关各自的未保存状态保护；设置导航、切页签、切项目、浏览器后退/刷新/关闭、上传等待取消均须验证。保存中禁止离开，不为路由切换丢弃输入。

## 6. 分阶段实施与停止点

本次整体同时涉及新管理查询契约和多处前端交互，合在一起实施会跨后端/前端，故在规划时拆分。各阶段均为“小/中”，没有保留“大”阶段；若范围扩大，实施前重新拆分。

### C1：集中管理查询契约

- **改动量等级：中。** 仅在 Python 记忆模块增加三个有界只读查询及 DTO，复用现有写入安全边界，不涉及数据库迁移或前端切换。
- **目标与范围：** 落地第 4 节全局资料列表、按资料的项目关系分页、按项目的使用关系管理列表；核验聚合统计、资料归属、草稿/停用/删除/解除状态及原接口隔离。当前旧页面继续运行。
- **非目标：** 改菜单/页面、增加批量写、改变共享可见性、修改创建自关联、检索、schema 或 Worker。
- **验收方式：** 聚焦 Ruff/静态检查，隔离 MySQL 手动 API/synthetic；覆盖多项目/多关联分页不重复、筛选/计数一致、固定摘要上限、无正文/原件泄露、缺失及失效来源、旧 OWNED/USED/共享目录不变。无需浏览器，无真实项目写入。
- **授权边界：** 仅新增兼容只读能力和本专题记录；不执行运行库迁移或全局数据修复，不自动进入 C2。
- **停止点：** 新端点可独立调用，旧页面及 Review 兼容验收通过；记录并本地提交后停止。

### C2：独立菜单与集中资料工作台

- **改动量等级：中。** 仅 React 菜单、路由、全局列表与既有详情/创建抽屉集成，C1 后端契约已完整，无跨端迁移。
- **目标与范围：** 独立菜单、新路由与旧链接兼容；“记忆资料”默认不选项目即可查看，支持分页/归属及使用项目筛选/有界关联摘要；创建时选择归属项目，维护调用使用正确归属；复用 M8/M9 格式及诊断能力。
- **可安全停留的中间版本：** 同时提供“项目使用配置”页签，先复用现有选项目后开关、资料关联、共享目录、反馈和旧策略能力。资料侧已有影响项目预览继续可用，本阶段不声称已提供最终“管理使用项目”抽屉；不会移走旧功能后让用户无处使用。
- **非目标：** 改后端契约、跨项目关联新交互、批量操作、归属转移、样式体系重构或开启项目。
- **验收方式：** 前端 build、必须浏览器验收；覆盖默认全局查看、分页/筛选、从 A/B 来源开详情并以正确 owner 写入、MD/TXT/DOCX/PDF/Skill、反馈只读、项目开关/旧关联可达、全部旧链接及未保存保护、窄屏。写操作用隔离数据/API，真实页只读。
- **授权边界：** 仅消费 C1 和原写接口；旧路由兼容与原功能访问必须一起交付，不部署或触发真实 Review，不自动进入 C3。
- **停止点：** 独立入口和全局资料管理可用，所有旧功能仍有入口；验收记录并本地提交后停止。

### C3：双向项目关联与易读状态

- **改动量等级：中。** 仅 React 新关联交互与既有项目使用配置整合，消费 C1 只读接口及原 CAS 写接口，无 schema 变化。
- **目标与范围：** 从资料打开“管理使用项目”、逐项目添加/修改/移除/恢复；项目使用配置改为关系管理列表，显示失效来源与阻断原因；从项目添加资料继续使用有资格的候选目录。统一“归属项目 / 使用项目”“已添加 / 已移除 / 按变更匹配”文案。
- **非目标：** 多项目原子批量保存、默认全项目应用、自动共享/发布/启用、跨项目共享案例、执行中记忆检索或向量库。
- **验收方式：** 前端 build、必须浏览器验收；A 维护共享规范、B/C 分别添加并设置不同范围，两方向查看同一关系；连续保存刷新 sourceVersion，409 保留输入、预算失败不误报成功、移除一项目不影响其它、停用来源仍可移除、恢复校验来源、私有及案例不能越界添加、草稿不能添加、开关不被关联动作修改。结合隔离 API 验证旧检索只取 ACTIVE/有效来源，已有冻结任务不变；窄屏及导航保护通过。
- **授权边界：** 只在隔离数据验证写操作，不批量修复真实关系，不改权限模型或调用真实模型；真实业务效果验收仍按 62 号文档另行选样。
- **停止点：** 三项用户目标和双向关联闭环均可验收；记录并本地提交，停在本专项，不自动进入 M10 或其他改造。

## 7. 验收总清单与交付约定

1. 未选项目进入记忆库即可看到跨项目的分页资料，私有/共享属性没有被自动修改。
2. 资料归属和使用项目清晰分列；选择 B 的使用配置不能将 A 的正文当作 B 的自有正文编辑。
3. 新建资料明确填写归属项目并提示默认自关联；没有虚构项目、无归属草稿或隐式归属迁移。
4. A 的共享规范能从资料侧添加 B，也能从 B 的项目配置找到；两侧显示同一范围、版本和状态。
5. 从 B 移除仅影响 B，停用资料展示所有影响项目；未发布/无效/预算冲突不能假装生效。
