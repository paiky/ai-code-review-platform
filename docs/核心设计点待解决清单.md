- 未经确认不自动转成实施任务，也不自动更新状态。

## C-01 Agent Review 跨仓库取证

### 现状

- Agent 只能读取当前任务 worktree。
- 同仓库不同模块可以搜索和读取。
- 不能主动访问其他 Git 仓库、服务或未授权源码。

### 初步思考策略

- 先维护显式“项目依赖关系”，不允许 Agent 自由发现任意仓库。
- 只允许读取同项目组内、已授权的关联项目。
- 每个关联仓库使用独立只读快照，禁止跨目录和符号链接绕过。
- Planner 先判断是否确实需要跨仓库证据，再按服务、符号和证据类型定向检索。
- 返回证据时携带来源项目、commit 和脱敏路径摘要，保证可追溯。
- 跨仓库证据只辅助判断，Finding 仍落在本次 changed files。

### 最小验证

- 先选择两个存在明确调用关系的非敏感测试仓库。
- 只验证一条调用链，例如“调用方接口 → 被调服务 DTO”。
- 对比启用前后的漏报、误报、耗时、Token 和源码暴露量。

### 边界

- 不开放任意 Git clone、Web、Shell 或全组织源码搜索。
- 未配置依赖关系或未授权时保持当前单仓库行为。

## C-02 Review 误判问题解决

### 现状

- 已有 `contextStatus / confidence / evidence / missingContext`。
- 已有评估样本、回放、质量看板、补证据和验收记录。
- 当前主要缺口是足量、可信的真实人工标注样本。

### 初步思考策略

- 先区分误判类型：证据不足、Prompt 问题、Retriever 问题、规则问题、模型问题。
- 误报和漏报分别治理，不能只降低 Finding 数量。
- 缺少证据时优先补证据，不直接增加 Prompt 禁止项。
- 单条反馈不自动生成全局规则，先观察是否在同类样本中重复出现。
- 每次修改前建立 baseline，修改后用同一批样本回放。
- 同时比较准确率、召回率、上下文不足率、耗时和成本。

### 最小验证

- 先积累一批去重人工样本，覆盖有效 Finding、误报和人工漏报。
- 每次只修一个高频误判类型。
- Candidate 未优于 baseline 时不扩大上线范围。

### 边界

- 不用“减少告警数量”代替准确率提升。
- 不因一次误报自动忽略安全、事务或数据一致性风险。

## C-03 多任务同时 Agent Review

### 现状

- 单个 Agent Worker 当前一次只领取并执行一个任务。
- 数据库领取任务已支持行锁；MySQL 8 可使用 `SKIP LOCKED`。
- 多个 Worker 理论上可以并行领取不同任务，但尚未形成正式并发策略和验收结论。

### 初步思考策略

- 第一阶段保持“单 Worker 单任务”，优先通过增加 Worker 副本横向扩容。
- 每个 Worker 使用独立 `workerId`、任务目录、Claude 进程和心跳。
- 增加全局、Provider、项目组三级并发上限，避免 API 限流和单项目挤占队列。
- 保留任务优先级和先进先出，同一任务重试不得同时运行。
- 继续使用 lease、幂等键和最终状态校验，防止重复提交。
- 记录排队时间、运行时间、并发数、失败率、限流和 Token 用量。

### 最小验证

- 从两个 Worker、两个小型非敏感任务开始。
- 验证任务不会重复领取，worktree、结果和进度不会串任务。
- 再逐步提高并发，观察 Provider 限流、CPU、内存和队列等待时间。

### 边界

- 暂不在单个 Worker 内直接启用多线程 Claude CLI。
- 没有资源和限流数据前，不开放无限 Worker 自动扩容。
