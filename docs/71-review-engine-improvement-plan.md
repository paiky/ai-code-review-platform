# 审查引擎优化与运营指标推进方案

2026-11-28。本文评估从 Open Code Review 借鉴的九个方向，适用于当前 Python 后端、Agent Worker 和 React 前端。上游机制以 `d4f568f` 为准。

**第一项上线内容是全量文件规则匹配。** 详细范围、规则资产、解析优先级、Prompt 注入、项目端类型兼容和生产验收见 [72 号文件规则首版落地与验收计划](72-file-rule-matching-rollout-plan.md)。

推进顺序为 **A0 与 72 的 F0 合并记录改前基线 → 72 的 F1–F5**。预算对照、已有 Worker 恢复验证、原文定位离线验证和反证复核对照各自交付。执行链路随后按 **B2A 离线分组 → B2B 组内单遍、两组并发 → B2C 完成组断点 → B3 同组第二遍** 推进。生产验证由用户安排。C1 由实测上下文压力决定，D1、D2 保持最低优先级。

**交付方式。** 各阶段使用正常 Review 入口，沿用项目现有策略、Runtime 与访问权限。正式调度从 Worker 现有 Runner 分发入口接入。每个发布单元提供自己可复现的验收和版本回退路径。分组与第二遍由任务输入和预算自动决定。样本不足的质量结论标明待生产验证。

## 1. 各阶段的改动、影响与验收

| 顺序 | 阶段 | 改动性质与等级 | 影响的现有设计 | 页面变化 | 你如何验收 |
|---|---|---|---|---|---|
| 先行 | A0 · 最小对照基线 | 复用，小 | 固定提交回放与评估记录 | 无 | 核对固定样本和改前请求，确认规则命中与未命中的预期。 |
| 首次上线 | A2 · 文件规则匹配 | 请求构建增量与端类型前置条件调整 | Agent / Standard、项目端类型与历史兼容 | 见 72 | 见 [72 的详细方案与验收](72-file-rule-matching-rollout-plan.md)。 |
| 独立验证 | B1 · 工具与轮次预算 | 配置对照，小 | Runtime 预算、收敛和终态提交期限 | 无 | 固定同个 diff 和模型，核对触顶、有效新增证据及耗时。 |
| 独立验证 | A4 · Worker 故障恢复 | 复用验证，小 | Compose 重启、租约与整任务重领 | 无 | 隔离环境停止 Worker，看任务接管、重跑和终态是否只出现一次。 |

| 独立验证 | A3A · 反证复核对照 | 离线增量，中 | Provider、人工评估和已有 Finding | 无 | 用已标注样本核对反证是否成立，并抽查被错判的真问题。 |
| 后续 | A1 · 原文定位接入终态 | 协议增量，大 | `submit_review`、Worker 完成回传、Finding 附加结果与旧读端 | 无，先通过附加结果验收 | 同一任务核对匹配坐标、歧义状态与旧反馈／修复引用。 |
| 执行链路 | B2A · 分组验证 | 离线增量，中 | diff 解析、Runner 输入切片与组外取证 | 无 | 看相关文件是否同组、全量文件是否覆盖、组外能否补证。 |
| 执行链路 | B2B · 两组并发单遍 | 局部重构，大 | Worker 单 Job 执行、预算分配、终态聚合、兼容领取 | 执行过程增加组状态 | 看两组确实重叠、整次只出一份正式结果，缺组时不会显示成功。 |
| 执行链路 | B2C · 完成组断点 | 协议与持久化增量，大 | 租约接管、组完成回传、旧 Worker 兼容 | 沿用组进度，标明复用与重跑 | 完成一组后中断 Worker，确认接管只重审未完成组。 |
| 执行链路 | B3 · 同组第二遍 | 组内流程增量，中 | 组调度、Prompt、预算和完成组检查点 | 执行过程增加遍次和新增数 | 看第二遍实际拿到首遍 Finding，复核新增数与重复去重。 |
| 执行链路 | A3B · 组内自动复核 | 后处理增量，中 | 每遍结果、组预算、检查点与裁决记录 | 结果详情展示复核状态和反证 | 核对反证与源 diff，模拟复核超时确认原 Finding 可读。 |
| 后续 | C2A · 异步定位 | 工具与回传增量，大 | Runner 工具协议、候选状态和领取代次 | 无，先通过回传验收 | 替身持续取证时收到候选 ID，定位随后完成，终态只提交一次。 |
| 后续 | C2B · 增量候选显示 | 前端增量，中 | 任务进度轮询、候选与正式 Finding 的关联 | 执行过程加候选与状态 | 审查进行中看到候选，刷新、取消和接管后状态仍准确。 |
| 按需 | C1 · 长对话压缩 | Runner 内部局部调整，中 | 对话历史、上下文预算与证据引用 | 无 | 复现长对话触顶，核对关键证据可重读及召回、Token 变化。 |
| 最低 | D1 · 运行总览重构 | 首页及指标接口重构，大 | 运行总览、质量监测跳转与指标数据口径 | 首页重排 | 固定时间窗对账人数、采纳与误报分母，并从指标追到代表任务。 |
| 最低 | D2 · 隐藏审计页清理 | 前端局部清理，小 | 已退役路由、导航及历史链接 | 移除已确认闲置页面 | 验证任务详情、质量监测和历史直达链接仍有可用去向。 |

后续每个方向进入开发时，交付说明都使用这四个问题核对。说明属于重构还是增量，具体影响的历史设计，页面布局或入口有何变化，以及用户如何在正常入口验证。阶段范围变化时同步更新改动量等级和验收方法。

复用现有运行预算、Worker 池和对话回放。文件规则首版以 `main` 的 `0b4a2f2` 为基线，使用固定提交与正常 Review 入口验收。质量监测专题尚未进入该基线，后续具备数据时可结合监测报告和人工 `EvaluationCase` 评估质量。 [运行预算](45-agent-review-runtime-budget-configuration-plan.md) · [Worker 池](47-agent-review-multi-worker-pool-and-queue-governance-plan.md) · [对话回放](68-agent-review-conversation-replay-plan.md)

## 2. 首批上线 · 文件级审查规则

**A0 改前基线与 A2 文件规则匹配。** 参考 Open Code Review 的文件规则，为已纳入审查的变更文件匹配检查清单，供 Agent 与 Standard 使用。新项目无需先选择端类型，已有项目继续沿用显式配置。

**进度与验收。** A0 / F0 基线、F1–F4 实现和 F5 本地验收已完成，生产验证待安排。详细记录、验收入口和回退方式统一维护在 72。 [文件规则详细推进与验收](72-file-rule-matching-rollout-plan.md)

## 3. 可独立验证的增强

### B1 · 预算对照

- **改动量等级：小。** 在现有预算契约内核对分配和内部默认值。
- **目标与范围**　现有默认 `maxTurns=12`、`maxToolCalls=40`、`maxEvidenceCalls=10`、`convergeAtCalls=8`、`submitByTurn=9`。区分模型交互轮次、总工具调用、取证调用和终态提交机会。选被相应限制提前截断的案例，先只提高一个预算维度，必要时按现有约束同步调整收敛或提交阈值并记录。另取一组没有触顶的样本检查成本。
- **非目标**　直接套用 OCR 的 100 轮、统一上调全部 Agent Review 的预算。
- **验收**　用同一模型和样本比较新增有效证据、高风险召回、提交成功率、P95、Token 及限流。确认额外轮次解决的是预算不足，工具空读、重复检索和材料缺失按对应原因处理。
- **授权边界与停止点**　用本地样本核对现有配置和分配规则，记录默认值依据后即可交付。生产验证通过正常审查入口观察用量和降级。
- **后续分组预算核对**　每遍的预算配置下限为 6 个模型轮次、4 次取证调用，实际可提前结束。B2B 两组首遍需分配至少 12／8，用现有默认额度核验。B3 两组首遍加一组第二遍需至少 18／12，届时对用平台默认预算的分组任务自动预留。自定义预算按已配置额度运行。只够首遍时，记录第二遍跳过原因。各组共享整任务截止时间及工具、取证和源码预算。

### A4 · Worker 自恢复与租约接管验证

- **改动量等级：小。** 首版以验证现有部署、队列和抢占机制为目标，具体缺陷出现后再评估修复范围。
- **目标与范围**　验证开发和运行时 Compose 的 `restart: unless-stopped`、在线兼容 Worker 接管和原任务重跑。单节点进程恢复由容器运行时负责。主机故障后能否接手取决于是否已有其他兼容节点和可访问的冻结材料。记录重启、心跳恢复、任务接管和重新执行的耗时及条件。
- **非目标**　新增集群弹性调度、提高领取上限、把对话回放当作恢复输入。当前重领从原输入开始，现有 `max_attempts=2`。
- **验收**　用受控替身或隔离部署复现进程崩溃、只有一个 Worker、存在第二个兼容 Worker、无兼容 Worker 和旧 Worker 迟到回写。核对没有重复终态、通知或重复降级。
- **授权边界与停止点**　在本地或隔离部署复现故障。现有机制满足场景时，以验收记录结束。发现具体缺陷时纳入最小修复，并复核阶段等级。

### A1A · 离线原文定位

- **改动量等级：小。** 仅在固定 diff 上验证定位和歧义处理，复用已有 diff 解析。
- **目标与范围**　用人工给定的原文引文核对旧侧、新侧、重命名、重复片段和缺失 diff，产出可复用的定位逻辑和状态口径。
- **非目标**　修改模型工具、正式 Finding、Worker 协议或页面。
- **验收**　固定样本逐条核对路径、行区间和匹配状态，确认歧义时不会自动选中一处。
- **授权边界与停止点**　离线定位可复现后独立交付，终态接入留给 A1。

### A3A · 反证复核对照

- **改动量等级：中。** 首版为离线或影子评估，复用评估记录，不改变正式结果契约。
- **目标与范围**　复核器只回答候选是否被当前代码的明确事实反驳。记录原 Finding 引用、反证位置、裁决、模型和复核失败原因。证据不足时保留并标记待人工核对。优先复核高严重度且证据不足、置信度高的候选。另抽样有风险信号的零 Finding 任务评估漏报。可复用 `refinementOverlay` 的附加结果模式，事实复核和现有定向补证各用明确语义。
- **非目标**　自动隐藏或降级正式 Finding、把复核模型裁决自动转成项目长期记忆、把影子结果用于通知和自动修复。
- **验收**　覆盖真阳性、明确反证、缺上下文、复核超时和错引文。人工核对复核前后查准率、高风险召回与额外耗时，并抽查复核建议移除的有效问题。未完成样本呈现为缺数据。
- **授权边界与停止点**　在固定样本上验收，交付可复核的评估记录。自动接入审查由 A3B 完成。
- **改动点与契约**　从固定样本捆绑的原结果和 patch 构造复核请求，复用现有 Provider 配置和 `EvaluationRun` 记录。每个输入候选使用稳定 ID，输出限 `KEEP`、`CONTRADICTED`、`NEEDS_CONTEXT`，另记执行失败。`CONTRADICTED` 必须带明确反证的文件、diff 侧和行区间，必要时附短引文，由程序校验出处。程序校验引用存在，事实是否构成反证由模型和人工样本核对。未知 ID、引用不合法、超时或缺材料均保留原候选，并记录原因。

### A1 · 原文定位接入终态

- **改动量等级：大。** 涉及模型提交 schema、Worker 后处理和可能被反馈或修复引用的 Finding 位置。
- **目标与范围**　复用 A1A 定位，在现有终态 `submit_review` 增加可选短引文，后端和 Worker 兼容接收。通过附加结果记录位置和状态。重复片段、材料缺失或无法匹配时保留 Finding。切换正式行号前核对反馈指纹、修复预览和历史兼容。引用原文留在执行作用域，进度使用安全坐标和原因码。
- **非目标**　逐条流式发布、把文本命中视为风险成立、将候选评论自动发往钉钉或 GitLab。
- **验收**　固定样本覆盖重复片段、删行旧侧、新侧、重命名和缺失 diff。对照错文件／错行率，核对旧 Worker、旧结果、缺引文、自动修复与反馈引用。无法定位的 Findings 计入分母。
- **授权边界与停止点**　后端兼容契约和定位附加结果可独立交付。回退应用版本后，旧链路仍可读取历史 Finding。
- 首版把模型可选入参、Worker 定位和后端附加结果作为一个发布单元，保证引文能够被完整消费并且可查询。
- **改动点与契约**　在 `agent_review_spike/schema.py` 的模型提交 schema 给 Finding 增加可选 `anchorQuote`（短原文及 `OLD`／`NEW` 侧，可省略侧）。`ReviewToolExecutor` 使用 `diff.py` 的文件归属解析和同一运行冻结的 diff 定位。旧侧只查旧侧，未指定侧且两侧命中产生不同坐标时标为歧义。模型引文在 Worker 校验后移除，正式 `/complete` 的 Review Card 保持原 schema。通过可选的 Worker 完成字段传入 `anchorResults`，Backend 核对文件及与 Review Card 的关联后存入附加结果。状态为 `MATCHED`、`AMBIGUOUS`、`UNMATCHED`、`UNAVAILABLE`。`MATCHED` 记录路径、侧和已核实的起止行，其他状态记录原因码。首版按已校验卡片的 Finding 序号关联，生成正式标识前校验重复或越界引用，避免影响原行号和反馈指纹。

## 4. 后续 · 审查执行与恢复

### B2A · 分组可行性验证

- **改动量等级：中。** 跨文件关系、审查输入和评估记录需要一起验证，执行限于隔离样本。
- **目标与范围**　优先依据现有文件和业务关系，让接口与实现、Mapper 与 DAO 等相关改动同组。首版用简单可复现的分组比较整任务单 Agent 与多个分组对话。固定总预算，检查分组是否丢掉组外证据和跨文件问题。
- **非目标**　接入正式 Worker 队列、持久化检查点、让模型决定全量分组或预先实现通用调度器。
- **验收**　同批样本核对文件覆盖、跨组依赖、重复报告、跨文件高风险召回、Token 和耗时。覆盖单文件、只形成一组、相关文件同组、独立改动均衡分配和材料不足的回退。
- **授权边界与停止点**　本地可交付分组策略与对照结果。生产验证依用户安排，风险召回无标签时标明未评估。
- **分组条件与契约**　沿用 OCR 的文件分组思路，以当前已经纳入审查的变更文件为分配单元。首版由程序按可核实的关系分组。变更中能确认的接口与实现、Mapper XML 与对应 DAO 等放在一起。模块路径作辅助，同扩展名本身不足以认定两个文件相关。无关联的文件可以分开。组数超过两组时，按 diff 规模将独立的组并入较小组，保留已确认关联。固定路径顺序、组 ID 和分组原因，全部纳入文件恰好出现一次。只有能形成两组、每组输入完整且预算足够时并发。单文件、全部文件实属一个关联组，或无法安全分组时沿用整任务审查。Agent 可按原有范围读组外源码补证，Finding 归属本组变更文件。
- **首个可见结果**　隔离演示先跑固定样本，输出两组的文件、开始和结束时间及 Finding。用替身传输证明两组请求在时间上重叠，并用同组串跑结果核对覆盖和汇总。正式队列集成进入 B2B。

### B2B · 两组并发单遍审查

- **改动量等级：大。** 组调度、共享预算、Worker 兼容和正式结果覆盖校验必须同时可用。
- **目标与范围**　用 B2A 的分组策略，在一个 `AGENT_REVIEW` Job 下最多两组并发，各组只审一遍。每个纳入文件有明确归属，组外源码按既有范围取证。只有必审组都完整时才提交一份正式结果。Worker 崩溃时继续沿用 A4 整任务重领，新的领取从冻结输入重跑所有组。
- **非目标**　完成组持久化、组级自动重试、第二遍、独立子任务通知和共享队列并发调整。
- **验收**　核对两组实际重叠、完整覆盖、重复 Finding、限流、取消、组失败和 Worker 重领后全量重跑。任一必审组失败时验证状态与现有降级路径，覆盖旧 Worker、旧任务及正常通知。单遍并发与同组串行比较同等覆盖下的耗时和 Provider 错误。
- **授权边界与停止点**　单遍并发完整通过后可独立上线，生产验证由用户安排。分发、预算和覆盖判断作为同一发布单元，保证缺组时不会产生成功结果。回退前处理好在途任务，再回退应用版本。

**具体改动与契约**

| 环节 | 首版实现 |
|---|---|
| 入队与领取 | 在现有冻结输入保存组计划。分组任务交给支持相应契约的 Worker，旧任务沿原协议运行。 |
| 执行与预算 | `worker.py::_run_job` 使用任务冻结的 Runtime。各组有独立对话、工具范围和结果目录，派发时受整任务预算约束，共享截止时间和取消信号。无法分配足够额度时走整任务审查。 |
| 汇总 | Worker 按稳定顺序汇总各组结果，复用现有 Finding 去重。Backend 校验必审组覆盖后走 `complete_job`。缺组或超出现有 Review Card 上限时记录原因并走现有失败及适用的降级流程。 |
| 可见进度 | 复用任务详情「执行过程」，显示组标识、文件数、运行状态和结束原因。正式 Finding 进入现有结果区。 |

### B2C · 完成组检查点与接管恢复

- **改动量等级：大。** 涉及 MySQL 持久化、领取与回传契约及新旧 Worker 兼容。检查点写入与读取必须一起交付。
- **目标与范围**　在 B2B 的组调度上保存已校验的成功组，包括零 Finding 结果。检查点绑定 Run、组、项目、Base/Head、组输入摘要和运行配置。接管后复用匹配的完成组，重新审查失败或未完成组。
- **改动点与契约**　按 `runId + groupId` 幂等保存，校验 Worker、租约和 `claimAttempt`。领取仅返回与冻结计划匹配的完成组，按剩余额度继续。检查点不可用时保留 B2B 整任务重领路径。后端和 MySQL 5.7 兼容迁移先于新 Worker 部署。
- **非目标**　从模型对话中间恢复、增加组级自动重试或同时引入第二遍。
- **验收**　完成一组时模拟 Worker 退出，用新领取代次继续。在现有组进度核对复用与重跑。覆盖零 Finding 检查点、重复写、迟到写、输入变更、预算不足和旧 Worker，确认只产出一份正式结果与通知。
- **授权边界与停止点**　隔离环境验收接管后独立上线。回退先处理在途任务，恢复整任务重领并保留已有检查点。生产验证由用户安排。

### B3 · 同组第二遍审查

- **改动量等级：中。** 复用既有审查组，调整组内调度、预算和结果归并。
- **目标与范围**　首版自动从两组中选至多一组执行第二遍。候选组须有首遍 `MAJOR` 及以上 Finding、现有结构化高风险信号或已确认的跨文件变更关系之一。优先按首遍最高等级排序，其次按已有风险信号、跨文件关系和稳定组顺序。首遍暂无 Finding 但仍有其他条件的组也可进入。第二遍带上首遍校验并去重的 Finding，继续找遗漏。两遍共用整组和整任务预算。
- **非目标**　所有项目默认两遍、第二遍替代事实复核、让同一问题重复通知。
- **验收**　在同一任务详情看见两个组的执行，以及指定组的第二遍和新增 Finding 数。用替身核对第二遍实际收到本组首遍 Finding、另一组完成后只输出一份正式结果。固定同组输入和总预算，对比「单遍加预算」与「两遍」。人工确认第二遍新增真阳性和重复率，报告高风险召回、触顶和耗时，并验证第二遍超时后的结果连续性。
- **授权边界与停止点**　配置沿用 B1 和现有 Runtime。隔离验收通过后独立交付，生产验证由用户安排。无需加审或预算不足时按首遍完成。
- **改动点与契约**　在 B2B 调度器上接入第二遍，复用 B2C 检查点保存各已完成遍次和被选中的组。第二遍新建对话，沿用本组 diff、取证范围及首遍 Findings。首遍失败按 B2B 处理。预算不足时记录跳过原因，用户取消沿用取消终态。第二遍失败且首遍完整时，汇总首遍并记录补充审查未完成。重复问题保留首遍位置和标识，新增 Findings 进入组汇总。进度记录 `groupId`、`passNo`、耗时、用量及结束原因。

### A3B · 主审查接入组内事实复核

- **改动量等级：中。** 复用 A3A 裁决契约、B2B 组结果和现有进度，首版仅记录复核结论。
- **目标与范围**　每组每一遍完成后，以该遍新增候选和对应 diff 发起一次有界复核。C2A 交付后，先收齐本遍定位结果再复核。各组独立，复用本次任务的 Runtime。复核的耗时和调用计入整任务预算。复用原 Finding 详情展示复核状态和反证位置。
- **改动点与契约**　在 Worker 的组内结果处理接入 A3A，沿组和遍次保存裁决及位置。复核失败保留已验证的组卡片，记录超时、证据缺失或响应不合法。若启用第二遍，将第一遍已保留的 Findings 交给下一遍找新问题。组检查点可复用已经完成且输入一致的裁决。
- **非目标**　自动删改正式 Finding、跨组全局仲裁、自动判定整次审查无漏报。
- **验收**　用替身验证只复核本组本遍的新候选、其他组可并行、超时可收敛、接管可复用结果。真实标注集对照按 A3A 口径记录反证命中、错误否定、高风险召回和耗时。
- **授权边界与停止点**　组内复核和结果查询通过验收后独立交付。复核裁决随原结果展示，正式 Finding 保留供人工判读。

### C2A · 审查中提交候选与异步定位

- **改动量等级：大。** 涉及模型工具 schema、异步处理和 Worker 到 Backend 的候选事件契约。
- **目标与范围**　A1 完成后，先用单组验证审查中的异步候选链路。`ReviewToolExecutor` 增加内置工具 `submit_candidate`，接收候选的路径、标题、说明和可选引文。工具校验组内文件归属后返回 `candidateId`，把定位工作派给有界评论池，模型可以继续查下一处。候选工具计入总工具调用，只在调查阶段开放。到 `submitByTurn` 后继续沿用 `submit_review` 的独立提交机会。
- **改动点与契约**　Worker 在同一领取代次内缓存候选。队列满、取消或定位失败时记录原因，终态仍可走 A1 定位。使用 `runId + claimAttempt + groupId + passNo + candidateId` 关联候选事件，单组和单遍使用固定值。上报用递增版本及 `PENDING_LOCATION`、`LOCATED`、`UNLOCATED`、`FINISHED`、`DISCARDED` 状态。候选可带独立的复核结论。`submit_review` 可以引用同作用域的 `candidateId`，也可直接提交 Finding。仅被最终卡片引用的候选关联正式结果，其余在取消或结束时归档为未采纳。Backend 按现有心跳与终态回传边界校验领取代次及状态版本。引文原文留在 Worker 执行作用域。
- **非目标**　让增量候选改变正式卡片、影响自动修复、写项目记忆或提前发送外部通知。
- **验收**　替身模型在继续取证前拿到候选 ID，定位可稍后完成。覆盖一次响应收取多条、入队失败、同一候选乱序更新、取消、接管、错误关联和 Worker 回传重试。检查最终卡片仍只提交一次，旧 Worker 和无候选事件的任务可读。
- **授权边界与停止点**　后端兼容接收和后台链路通过验收后独立交付，C2B 使用该协议展示候选。回退应用版本后可沿用 A1 终态定位。

### C2B · 执行过程显示增量候选评论

- **改动量等级：中。** 复用 C2A 事件和当前任务详情进度轮询，新增候选的视图与正式结果链接。
- **目标与范围**　在现有「执行过程」里显示本次领取代次的候选评论，标记审查中、已定位、待复核和最终去向。先上线兼容旧数据的读端。候选事件只展示经白名单和长度校验的标题、简短说明、相对路径、行区间和状态。刷新页面可通过现有进度接口恢复，终态链接到同一 `reviewKey` 的正式结果。
- **非目标**　同时更换轮询协议、让候选计入正式问题统计、向钉钉或 MR 提前发布候选。
- **验收**　用浏览器和替身模型验证审查尚未结束时可看到首条候选，覆盖乱序、重复、接管、取消、完成、降级以及历史任务。确认领取代次切换后旧候选的终态与本次活动候选可区分，正式结果链接准确。记录提前可见时间、总耗时和回传开销。
- **授权边界与停止点**　完成前端 build 和任务链路验收后独立交付，候选显示沿用任务详情已有的访问范围。

### C1 · 单次长对话压缩

- **改动量等级：中。** 首版限定一个 HTTP Runner 的消息重建和诊断，复用现有取证预算和白名单。
- **目标与范围**　有实际上下文触顶或长对话取证成本证据时启动。保留固定指令和初始审查输入、最近完整工具交互。较早工具结果只压缩可替代内容。对尚未出 Finding 的关键证据保留提交、路径、行区间和来源工具引用，允许重读原文。已提交结论由独立结果记录承载。先验证同步压缩，只有延迟数据说明有必要时再考虑后台压缩。
- **非目标**　修改 Claude CLI 自身压缩、做跨任务记忆、用压缩结果替代崩溃检查点、直接照搬 OCR 的 60%／80% 阈值。
- **验收**　复现上下文压力，比较压缩前后关键证据的可恢复率、真实问题召回、Token 和耗时。覆盖摘要遗漏、不可用或重建超限。此前的已提交结论可追溯，无法压缩时按现有预算终止并保留诊断。
- **授权边界与停止点**　固定样本或替身传输先行。若缺乏收益证据，停在观测。隔离验收通过后再评估其他 Runner。

## 5. 最低优先级的页面工作

### D1 · 运行总览改为运营指标入口

- **改动量等级：大。** 运营口径、后端聚合接口和首页一起变化，部分指标可能涉及新的可信事件来源。
- **目标与范围**　先验证指标的数据可得性，再改 `/` 的运行总览。首页优先给工作人员展示项目和时间范围内的核心指标、变化、覆盖和待改进问题入口。实时运行诊断保留可访问入口，质量监测继续承接具体样本和问题。

  | 指标 | 拟定口径与当前限制 |
  |---|---|
  | 人员月活 | 自然月内执行约定审查操作的去重人员数，以可信账号或身份事件为准。自动 webhook、机器人和手填姓名排除。现有反馈表仅有可选 `operatorUsername`，不足以推算平台人员月活。可用数据源确认前显示暂无数据。 |
  | 建议采纳率 | 存在可信采纳或合并证据的正式建议数 ÷ 同口径下可追踪的已发布正式建议数，同时展示追踪覆盖。现有 `USEFUL`、`FIXED` 可分别展示有用与标记已修复的反馈。MR 实际合并且能归因到具体建议，或存在等效的采纳证据时，可计入已证实采纳数。 |
  | 样本误报率 | 人工判定为误报的正式 Finding ÷ 可裁决的已抽样正式 Finding。采样范围、有效分母、未知或重复的处理方式单独展示。总体误报率依赖代表性抽样。零 Finding 样本用于独立看漏报。 |

- **非目标**　用任务数替代人员月活、用生成补丁或加入修复队列替代实际采纳、回填无法确认的历史数据、复刻上游内部指标。
- **验收**　选固定时间窗，用原始记录人工对账分子、分母、去重及未知状态。核对权限、零值和缺数据区别、跨项目访问、首页到代表任务和监测问题的定位。完成前端 build 和浏览器验收。
- **授权边界与停止点**　先交付数据口径与可用性核对，再决定页面和 API 范围。若需要采集新的人员事件，先明确其采集范围与使用权限。在数据可证明且可从页面追到代表任务后结束，回退可切回现有总览入口。

### D2 · 清理确已停用的隐藏审计页

- **改动量等级：小。** 首批限已确认无消费方的前端入口、组件和资源。涉及后端契约、存量数据或兼容路由时重新评估。
- **目标与范围**　从 `frontend/src/appShell.js`、`App.jsx` 的导航开关及实际路由出发，核对旧质量看板、规则缺口、评估样本、验收记录、回放记录和反馈池的消费方。任务详情仍有规则缺口链接，监测还可能引用评估或回放。清单应记入口、直达链接、引用方、替代入口和处置结果。D1 完成后更新引用清单，再清理已确认无需保留的页面。
- **非目标**　删除审计数据、拆除仍被监测或评估使用的 API、根据侧栏隐藏直接删除路由。
- **验收**　全仓核对导航、直接链接、任务详情、通知、文档和监测链路。删除后完成前端 build 和浏览器检查。涉及曾使用的公开链接时明确跳转目标。
- **授权边界与停止点**　先停在可审阅的页面清单。需要退役仍有消费方的入口时，先明确迁移范围。已确认的页面清理完成后独立交付，可用前端回退版本恢复。
