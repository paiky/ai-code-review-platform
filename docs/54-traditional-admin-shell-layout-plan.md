# 传统后台管理壳层布局改造计划

## 1. 状态、结论与停止点

- 文档状态：**阶段一、阶段二 A、阶段二 B、阶段二 C 均已完成并进入当前基线（2026-08-08）**。
- 可行性结论：**可行**。当前 React 应用已经由统一 `AppFrame` 承载普通顶栏、路由内容、失败通知和调度队列，
  可以在不修改 Backend、数据库和业务接口的前提下改为“左侧菜单 + 右侧全局顶栏 + 内容区”的传统后台布局。
- 风险等级：**中等**。主要风险不在路由迁移本身，而在桌面侧栏占用后的页面有效宽度、平板和移动端响应式行为、
  Command Center 的视口高度计算，以及 Review 运行态沉浸工作台不能残留普通壳层。
- 当前停止点：**54 专项全部规划阶段均已完成**。本次不再继续扩展统一连接池或其它设置能力，也不自动提交、推送或
  部署；后续新增需求必须重新明确范围和授权。

## 2. 需求目标与参考边界

### 2.1 用户目标

将当前横向顶部导航调整为传统后台管理布局：

- 左侧展示品牌和主菜单；
- 右侧工作区顶部展示跨页面的全局信息和操作；
- 页面主体继续承载现有运行总览、任务、设置和其它业务页面；
- 桌面侧栏可折叠，并兼容平板、移动端和现有 Review 沉浸工作台。

壳层改造完成后，在同一设置页面内将 Agent Review 与 Standard Review 的运行配置、模型连接目录和原生详情编辑器
聚合为一个工作台，使用户能够在一个上下文中理解两种 Review 的当前选择、连接状态和配置入口。

### 2.2 参考图使用边界

参考图只用于壳层位置、信息层级、留白和操作归属，不作为页面能力清单。首期不照搬参考图中的知识库、成员与权限、
审查规则、用户头像或管理员菜单，也不将当前设置页拆成多级页面。

本专项遵循“布局迁移，不重做信息架构”：

- 保留现有路由、页面文案和功能开关；
- 不因侧栏可容纳更多项目而开放隐藏中的质量治理入口；
- 不伪造当前系统没有的登录用户身份；
- 阶段一不改变各业务页面内部卡片、表格、表单和工作流；阶段二只聚合设置页的模型配置入口，不改变配置语义。

模型配置参考图同样只作为信息层次和列表/详情布局参考。阶段二不照搬以下当前没有的能力：

- 不增加或删除连接；Provider 继续使用 Backend 返回的固定目录；
- 不持久化普通 Provider 的最近测试时间和延迟，测试结果只在当前详情会话展示；
- 不伪造独立的 Standard Review 开关，平台级能力仍由现有全局开关控制；
- 不提供静态 Agent fallback Provider 下拉框；Agent 失败后继续执行项目端类型、项目、项目组模型、Profile 和全局默认
  Provider 组成的 Standard 动态解析链；
- 不把 Agent 与 Standard 称为共享连接池，不复用 Agent 独立加密 Key 和普通 Provider Key。

## 3. 当前实现与改造基础

当前普通应用壳层集中在 `frontend/src/App.jsx` 的 `AppFrame`：

- `Header.app-header` 同时承载品牌、运行总览、任务、质量治理、设置、版本更新、接入帮助、失败通知和调度队列；
- `Content` 直接承载全部 React Router 路由；
- 失败通知与调度队列的状态、轮询、打开动作和 Modal 已经由 `AppFrame` 统一管理；
- `ReviewWorkspaceModeContext` 会在当前任务进入沉浸模式时隐藏普通 Header，并为 Content 切换沉浸样式；
- `frontend/src/styles.css` 已经以 `760px`、`1000px`、`1180px` 等断点处理普通顶栏和沉浸工作台；
- Command Center 使用 `calc(100dvh - 56px)` 计算普通壳层下的最小高度。

因此阶段一无需改变页面级数据流，核心工作是重组 `AppFrame` 的展示结构，并统一壳层尺寸和断点契约；阶段二继续复用
现有设置请求，只在前端建立统一展示模型和分域操作入口。

## 4. 目标壳层结构

普通页面采用嵌套 Layout，页面继续使用文档级滚动，不新增独立内容滚动容器：

```text
AppFrame
├─ AppSidebar：品牌、主导航、折叠控制
└─ MainLayout
   ├─ GlobalHeader：移动端菜单、版本、帮助、失败通知、调度队列
   └─ Content：现有 Routes、JobQueueModal、FailureNotificationsModal
```

目标 DOM 和样式必须满足：

- 外层最小高度为 `100dvh`，右侧 MainLayout 设置 `min-width: 0`，避免表格或长内容撑破文档宽度；
- 侧栏占满视口高度并保持在左侧，品牌区与右侧顶栏统一为 `56px` 高；
- 右侧顶栏使用 `position: sticky; top: 0`，页面继续由浏览器文档滚动，避免 Drawer、Modal 和沉浸页面出现双滚动；
- Content 不统一增加新的最大宽度或卡片容器，保留各页面现有的 `TaskWorkspaceShell`、`page-shell` 和
  Command Center 布局规则；
- 普通壳层隐藏时，侧栏、顶栏及其宽度占位必须一起移除，不能只设置视觉隐藏。

## 5. 导航与全局操作契约

### 5.1 左侧导航

| 导航项 | 路由或条件 | 选中规则 |
| --- | --- | --- |
| 运行总览 | `/` | 仅根路由精确匹配 |
| 任务 | `/tasks` | `/tasks` 及 `/tasks/:taskId` |
| 质量治理 | 继续受 `QUALITY_GOVERNANCE_NAV_VISIBLE` 控制 | 按现有质量治理子路由最长前缀匹配 |
| 设置 | `/settings` | `/settings` 前缀匹配 |

质量治理启用时，继续复用现有质量看板、评估样本、规则缺口、验收记录、回放记录和受独立开关控制的反馈池；横向
Dropdown 改为侧栏子菜单，但路由、顺序、图标和功能开关语义不变。当前开关关闭时不得显示空分组或占位项。

侧栏品牌区使用现有 Ant Design 图标体系和“AI代码质量审查平台”文本，不增加图片、远程资源或新依赖。折叠时只展示
可识别的品牌图标，品牌按钮仍可返回根路由，并保留明确的 `aria-label`。

### 5.2 右上全局区域

右上操作固定按以下顺序展示：

1. 帮助（复用接入帮助路由）；
2. 版本（复用版本更新路由）；
3. AI Review 失败通知；
4. AI Review 调度队列。

“帮助”和“版本”分别复用现有接入帮助、版本更新路由；失败通知继续复用失败数量、危险态和原 Modal；调度队列继续复用活动数量 Badge、
轮询、取消和打开任务行为。不得修改请求地址、刷新周期、错误降级或 `AppFrameOperationsContext` 对外能力。

右上区域不显示“管理员”、头像、账户菜单或退出入口。未来接入真实身份体系时应另建专项，不在本布局中预留虚假数据。

### 5.3 路由与交互

- 使用 Ant Design Menu 的选中和展开能力承载主导航，不用仅靠颜色区分当前页面；
- 导航后继续传递现有 `location.state.from` 语义，详情页返回行为不变；
- 折叠图标需提供 Tooltip，所有图标按钮需提供可访问名称和清晰的键盘焦点；
- 移动端 Drawer 选择导航后自动关闭，Escape、遮罩点击和显式关闭按钮均可关闭，并将焦点还给菜单触发按钮；
- 浏览器前进、后退和直接访问详情路由时，菜单选中状态必须由 `location.pathname` 派生，不能依赖点击时保存的状态。

## 6. 响应式与折叠状态契约

### 6.1 桌面：视口宽度 `>= 1200px`

- 侧栏展开宽度 `224px`，折叠宽度 `72px`，首次访问默认展开；
- 折叠只影响品牌文本和菜单标签，不隐藏菜单项或改变路由；
- 折叠按钮位于侧栏底部，具有“收起菜单”或“展开菜单”的动态可访问名称；
- 用户主动折叠或展开后，将布尔偏好保存到
  `ai-code-review.app-shell.sidebar-collapsed.v1`。

存储值只接受字符串 `true` 或 `false`；缺失、读取异常或其它值一律按 `false`，即默认展开。写入失败不得阻断导航或
页面渲染。

### 6.2 平板：视口宽度 `761px–1199px`

- 固定保留 `72px` 图标栏，避免展开侧栏持续压缩表格和 Command Center；
- 点击展开按钮时，以覆盖内容的临时浮层展示 `224px` 完整菜单，不改变右侧内容宽度；
- 浮层选择菜单、点击外部或按 Escape 后关闭，并恢复触发按钮焦点；
- 平板自动折叠和临时展开不读写桌面折叠偏好，回到桌面时恢复用户原有桌面选择。

### 6.3 移动端：视口宽度 `<= 760px`

- 不渲染固定侧栏或其宽度占位；
- 顶栏左侧展示菜单按钮和精简品牌，菜单按钮打开移动端 Drawer；
- Drawer 宽度为 `min(280px, 88vw)`，包含完整品牌、主导航和折叠侧栏中的全部可见入口；
- 右上全局操作保留四项真实能力，空间不足时“帮助”和“版本”使用图标与 Tooltip/`aria-label`，不删除功能；
- 移动端 Drawer 开关为会话内临时状态，不写入桌面折叠偏好。

### 6.4 断点切换

- 从移动端或平板切换到桌面时，必须关闭 Drawer/浮层并恢复桌面偏好；
- 从桌面切换到平板或移动端时，不覆盖已经保存的桌面偏好；
- 任一断点都不得出现侧栏和 Drawer 同时可交互、不可见遮罩拦截页面、横向页面滚动或壳层双滚动。

## 7. Review 沉浸模式兼容

`ReviewWorkspaceModeContext` 和 `resolveReviewWorkspaceFrame` 继续作为普通壳层是否显示的唯一业务来源：

- 当前任务详情为沉浸模式时，不渲染 AppSidebar 和 GlobalHeader，Content 不保留左侧宽度、顶栏高度或普通页面 padding；
- terminal、非法模式、离开任务详情路由和组件卸载时，继续恢复普通壳层；
- 沉浸模式下不显示或后台保留移动 Drawer、平板浮层及其遮罩；进入沉浸模式前应关闭这些临时层；
- 不修改 ReviewJourney、当前 `reviewKey`、轮询、Canvas、Drawer、Popover、Finding、Diff、Patch 或结果数据；
- 普通壳层的折叠偏好不因进入或退出沉浸模式而改变。

## 9. 前端实现设计

### 9.1 阶段一：传统后台壳层

实施时将导航配置和路径选中规则从 `AppFrame` 的 JSX 中提取为可独立测试的纯展示模型，`AppFrame` 继续负责现有全局
请求、轮询和 Modal 状态。壳层组件只接收以下展示和操作输入：

- 当前 pathname 和功能开关；
- 桌面折叠、平板浮层、移动 Drawer 状态；
- 导航回调；
- 失败通知数量、调度活动数量和两个打开动作；
- 是否处于 Review 沉浸模式。

不新增公开 HTTP 接口或业务 schema。唯一新增的持久化界面是浏览器本地偏好键
`ai-code-review.app-shell.sidebar-collapsed.v1`；该键不承载身份、任务、Review 或其它业务数据。

样式应使用明确的壳层 CSS 变量统一 `56px` 顶栏高度、`224px` 展开宽度和 `72px` 折叠宽度，并审计现有
`100vh/100dvh - 56px/64px` 计算。只修正由壳层尺寸变化直接造成的高度和宽度问题，不顺带重构页面样式。

### 9.2 阶段二：统一 Review 模型配置工作台

#### 9.2.1 聚合边界

将现有“模型 Provider 配置”和“Agent Review”两个折叠项合并为一个“模型连接与 Review 配置”折叠项；项目组、
Profile、全局设置及其它折叠项的顺序和行为不变。

统一只发生在展示和操作入口，Backend 仍保持三套原生契约：

| 配置域 | 读取 | 保存 / 操作 | 凭据与测试 |
| --- | --- | --- | --- |
| 平台 Standard 默认值 | `GET /api/code-quality-reviews/settings` | `POST /api/code-quality-review-providers/{code}/set-default` | 不包含 Key，不发起模型请求 |
| Agent Review | `GET /api/code-quality-reviews/agent-settings` | `PUT /api/code-quality-reviews/agent-settings` | 独立加密双 Key；`POST .../agent-settings/test` 异步测试 |
| Standard Provider | `GET /api/code-quality-review-providers` | `PUT /api/code-quality-review-providers/{code}` | Provider 自有 Key；`POST .../{code}/test` 同步测试 |

不新增聚合 API。页面继续并行读取三份数据，前端通过纯展示模型生成运行配置卡和连接目录；任一请求失败时沿用设置页
整体错误处理，不以另一份成功数据伪造完整配置。

#### 9.2.2 顶部运行配置

顶部使用两张等高运行配置卡：

- **Agent Review**：真实启用开关、运行时选择、当前模型、Custom Runtime 推理强度、Worker Pool、Key 和配置完整性状态；
  fallback 只读显示“失败后继承 Standard 动态解析链”，不可直接选择某个 Provider；
- **Standard Review**：默认 Provider 选择、只读协议、模型、超时、Provider 启用和 Key 状态；不增加独立 Standard
  开关，平台全局启用状态只作为只读状态展示并继续在“全局设置”中修改。

两张卡均使用显式保存：Agent 保存调用现有 Agent Settings PUT；Standard 的“保存默认连接”只调用现有 set-default。
选择未配置完整的 Agent Custom Runtime 时，页面切换到对应详情并提示先补齐配置，不提交半成品；选择未启用或未配置 Key
的 Standard Provider 时允许保持现有 Backend 兼容行为，但必须展示明确警告，不能把它显示为可用。

#### 9.2.3 模型连接目录

目录按 Agent Runtime 在前、Standard Provider 在后生成稳定行：

- Agent 行 ID：`AGENT:<runtimeType>`；
- Standard 行 ID：`STANDARD:<providerCode>`；
- 列：名称、所属 Review、协议、Endpoint、模型、默认/当前状态、配置状态、更新时间和详情操作；
- Agent 的 `updatedAt` 属于整个 Agent Settings，只作为设置更新时间展示，不宣称是单个 Runtime 的独立更新时间；
- 不展示不可可靠恢复的最近测试时间和延迟，不提供新增、删除、分页或使用范围复选框。

初次加载默认选中 Standard 默认 Provider；不存在时选中 Agent 当前 Runtime，再回退到首行。重新加载数据时，原行仍存在
则保持选中，否则重新应用上述顺序。Standard 行只标识“Standard 默认”或“可供 Standard 使用”；不能根据 Provider
列表猜测项目、项目组、Profile 或 Agent fallback 的实际使用关系。

#### 9.2.4 原生详情编辑器

目录右侧或下方只渲染当前行对应的原生详情：

- Agent 默认 Runtime：固定 Endpoint/模型、独立 DeepSeek Key、保存、异步配置测试和清除 Key；
- Agent Custom Runtime：名称、只读 Responses 协议、Base URL、模型、推理强度、TLS 校验、独立 Key、安全状态、
  Worker 支持、保存、异步测试和清除 Key；
- Standard Provider：名称、只读协议类型、Endpoint、模型、超时、Provider Key、启用状态、保存、同步测试和清除 Key；
- Agent 执行预算保留为工作台底部的独立全宽区域，不归属于当前连接行，也不因选择 Standard Provider 而消失。

Provider 详情保存只调用 Provider PUT，不再隐式调用 set-default；设置默认 Provider 只由顶部 Standard 卡负责。Agent 测试
继续先保存当前 Agent 草稿并按 requestId 轮询，Provider 测试继续使用当前未保存草稿且只在会话内展示结果。

页面为当前详情维护 dirty 状态。用户选择其它目录行时，如名称、Endpoint、模型、超时、启用状态、TLS、推理强度或 Key
草稿存在未保存变化，先弹出丢弃确认；确认后恢复该连接最近一次服务端数据，取消则保持当前行。保存或清除 Key 成功后
清除 dirty；页面路由离开行为保持现状，不新增全局 beforeunload 拦截。

#### 9.2.5 响应式

- `>= 1200px`：顶部双卡；下方目录和详情双栏，目录优先获得宽度，详情最小宽度 `360px`；
- `761px–1199px`：顶部双卡保持并排，目录和详情上下排列，不让侧栏或详情压缩表格；

## 10. 风险与回退

| 风险 | 控制方式 |
| --- | --- |
| 侧栏压缩后表格或 Command Center 溢出 | 桌面/平板采用不同展开策略，MainLayout 设置 `min-width: 0`，执行三档浏览器验收 |
| 沉浸模式残留侧栏宽度或顶栏高度 | 由 `reviewWorkspaceFrame.immersive` 控制整个普通壳层是否渲染，补路由切换回归 |
| 响应式切换留下 Drawer 遮罩 | 断点变化和沉浸模式变化时统一关闭临时层，覆盖焦点恢复测试 |
| localStorage 异常阻断应用 | 读写封装为容错纯逻辑，非法值回退默认展开，异常不向业务层传播 |
| 通知或队列迁移后停止刷新 | 保留现有状态、生命周期和 Context，只调整触发器位置，补请求与打开行为源码契约 |
| 全局顶栏拥挤 | 宽屏显示文字，窄屏使用图标和可访问名称，不删除真实操作 |
| 统一目录误导为共享 Key | 使用 Agent / Standard 域标签和原生详情，文案明确“统一视图、分域保存” |
| Provider 保存意外切换默认值 | Provider PUT 与 set-default 动作分离，分别补请求契约测试 |
| 目录切换丢失未保存配置或 Key | dirty 状态和丢弃确认；确认后从最近一次服务端数据恢复 |
| Agent fallback 被误解为固定 Provider | 顶部只读展示动态解析链，不提供静态 Provider 下拉框 |
| 参考图状态列无法由现有 API 支撑 | 只展示真实配置状态；不伪造最近测试、延迟和实际项目使用范围 |

本专项没有数据迁移。阶段一回退时恢复原普通 Header 和相关样式，新增 localStorage 键即使保留也不会影响旧版业务；
阶段二回退时恢复原“模型 Provider 配置”和“Agent Review”两个折叠项及 Provider 保存后设默认的旧交互，不需要恢复
Backend 或数据库。

- 安全 mock 完整异常验收覆盖 Agent `QUEUED -> RUNNING -> SUCCESS / FAILED`、Provider 同步失败、三份读取失败后的
  页面内重试恢复、保存失败后 dirty 保留；未使用真实 Key、源码或真实 Provider，没有产生模型费用；
- 浏览器未发现产品运行异常；控制台仅保留工作台改造前已存在的 Ant Design `InputNumber addonAfter` 和其它 Drawer
  `width` 弃用提示，不影响本专项行为，未在阶段二 C 扩大范围处理。

最终遗留边界：

- 本专项没有执行真实 Agent Worker 或 Provider 联通请求；真实环境连通性继续由现有配置测试能力和有权限的运维验收
  负责，不能用安全 mock 结果推断外部服务可用性；
- 设置页仍由单次一致性加载聚合多个配置域；任一核心读取失败时整页进入错误态并允许重试，不提供部分数据编辑，这是
  为避免跨版本草稿混写而保留的现有安全边界；
- 既有 Ant Design 弃用提示和 `App.jsx` 体量治理不属于 54 的产品目标，后续如需处理应单独立项，不在本阶段顺带重构。
